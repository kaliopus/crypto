# Приватный 70B LLM через Phala Cloud (confidential GPU)

Готовый комплект, чтобы поднять свою модель на 70B параметров так, чтобы
провайдер физически не мог прочитать промпты, и общаться с ней по API
с вашего ноутбука.

## Как это работает

- Ваш ноутбук — единственное место, где промпты видны в открытом виде.
- Модель (vLLM, OpenAI-совместимый API) работает внутри confidential VM
  на GPU Phala: Intel TDX шифрует память CPU, NVIDIA Confidential
  Computing шифрует память GPU. Оператор облака не имеет доступа ни к
  той, ни к другой.
- Какие именно GPU доступны для самостоятельного заказа, Phala меняет
  без предупреждения: например, тариф H100 весной 2026 был на странице
  цен, а к сентябрю 2026 с публичной страницы `cloud.phala.com/about/pricing`
  пропал — сейчас там только H200 и B300. Перед деплоем всегда проверяйте
  актуальный список командой `phala instance-types` и `cloud.phala.com/about/pricing`,
  не полагайтесь на цифры из этого README.
- Перед тем как довериться эндпоинту, клиент проверяет криптографическую
  аттестацию: подписанное подтверждение, что запущен именно ваш
  `docker-compose.yml`, а не подменённый образ.
- Весь трафик между ноутбуком и энклавом идёт по TLS, который
  терминируется внутри энклава, а не на балансировщике провайдера.

Это даёт доказуемую, а не просто «на слово», приватность — в отличие от
обычной аренды GPU-сервера.

## Что нужно сделать вам (я не могу сделать это за вас)

У меня нет доступа к вашей оплате и аккаунтам, поэтому эти шаги — на
вашей стороне, с вашего ноутбука:

1. Зарегистрироваться на https://cloud.phala.network и привязать оплату.
2. Поставить CLI: `npm i -g @phala/cli`
3. Войти: `phala auth login`
4. Если модель — Llama (gated веса), получить токен на
   https://huggingface.co/settings/tokens и принять лицензию на странице
   модели.

## Запуск

```bash
cd infra/private-llm
cp .env.example .env
# впишите VLLM_API_KEY (придумайте сами, любая длинная случайная строка)
# и HF_TOKEN

# узнайте актуальный код GPU-тарифа (названия и наличие меняются)
phala instance-types

GPU_TYPE=<код из предыдущей команды, например h200:1> ./deploy.sh
```

Скрипт создаст CVM с одной GPU выбранного тарифа, поднимет vLLM с
`Meta-Llama-3.1-70B-Instruct-AWQ-INT4` (4-битный квант, около 40 ГБ
VRAM — комфортно влезает в любой актуальный тариф Phala, включая H200
141GB). Первый запуск займёт 10–20 минут — скачивание весов.

Проверить аттестацию перед первым реальным запросом:

```bash
./verify.sh
```

Отправить запрос с ноутбука:

```bash
pip install openai
PHALA_ENDPOINT=<url из `phala cvms get private-llm-70b`> \
VLLM_API_KEY=<из .env> \
python3 client.py "привет"
```

Дальше используйте любой OpenAI-совместимый клиент — `base_url` это ваш
эндпоинт + `/v1`, `api_key` — ваш `VLLM_API_KEY`, `model` — `llama-70b`.

## Стоимость (проверено на `cloud.phala.com/about/pricing`, сентябрь 2026)

| GPU | On-demand | 30 дней | 180 дней |
|---|---|---|---|
| H200 141GB | $4.80/ч | $4.30/ч | $3.80/ч |
| B300 288GB | $9.00/ч | $8.50/ч | $7.80/ч |

H100 на публичной странице цен на сентябрь 2026 отсутствует (раньше был
дешевле, около $3/ч) — возможно, временно распродан или снят с
самостоятельного заказа. Если он снова появится в `phala instance-types`,
он будет дешевле и для 4-битного 70B этого достаточно, второй GPU не
нужен.

Минимальная аренда H200 — 24 часа, у B300 — 30 дней. Остановить:
`phala cvms delete private-llm-70b` (счётчик идёт, пока VM существует,
даже без запросов — Phala явно предупреждает, что "стоп" не ставит GPU
на паузу).

## Смена модели

Поменяйте `MODEL_ID` в `.env` и перезапустите `./deploy.sh`. В 4-битном
кванте (около 40 ГБ VRAM) на любой актуальный тариф Phala с одной GPU
помещается:

- `hugging-quants/Meta-Llama-3.1-70B-Instruct-AWQ-INT4` (по умолчанию)
- `Qwen/Qwen2.5-72B-Instruct-AWQ`
- `casperhansen/deepseek-r1-distill-llama-70b-awq`

Для MoE-моделей вроде gpt-oss-120b, которые по качеству на сентябрь 2026
часто обгоняют плотные 70B при сравнимой цене, тоже хватает одной GPU —
второй заказывать не нужно.

## Ограничения

- Аттестация подтверждает код и модель, но не защищает от логирования
  на уровне вашего собственного клиента или сети между ноутбуком и Phala
  (используйте TLS — он включён по умолчанию через vLLM + Phala ingress).
- Если вы измените `docker-compose.yml`, старая аттестация больше не
  соответствует новому образу — проверяйте `verify.sh` заново после
  любых изменений.
- Это не резервируемый SLA-сервис: при аварии CVM модель нужно поднимать
  заново (`./deploy.sh` идемпотентен).
